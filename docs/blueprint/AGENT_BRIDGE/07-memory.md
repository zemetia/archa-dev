## Idea

Chat runs start clean on purpose: Claude Code gets an isolated config dir, so the person's own CLI memory never reaches a design run ([02](./02-roster-profiles.md)). ArchaDev keeps **its own** memory instead. It works the same for every agent CLI because it goes through the core and MCP, not through a CLI feature.

## Scopes

| Scope | Folder | What goes there |
|---|---|---|
| `global` | `ARCHA_HOME/memory/` | The person's taste and standing rules ("no labels above headings"), lessons from runs that went wrong |
| `document` | `<name>-data/memory/` | Rules for this design only: brand colours, tone, content the client refuses. Travels with the `.archa` → [FILE_FORMATS/01](../FILE_FORMATS/01-archa.md) |

An unsaved document's memory lives in its runtime data folder and moves with the first save.

## File

One fact per Markdown file, `<slug>.md` (slug from `name`, or the first sentence; `-2`, `-3` on a clash):

```markdown
---
name: "No small labels above headings"
updatedAt: 1764123456789
---

Never put small labels (eyebrows) above headings unless asked.
```

Id = `<scope>:<slug>`. Hand-written files work too: no frontmatter → the file name is the name and the modification time is `updatedAt`. Empty files are skipped. Writes go through a `.tmp` + rename.

## How runs use it

| Step | Rule |
|---|---|
| Read | The **first turn** of a thread carries a `Memory —` block after the skill lines: newest first, at most 40 facts and 6000 characters (`forPrompt`), then a count of the ones left out. Later turns do not repeat it |
| Write | `remember { text, scope, name?, replaces? }`. `replaces` rewrites an existing fact (removes it, writes the new one) so corrections do not pile up as near-duplicates |
| Remove | `forget { id }`; unknown id → `NOT_FOUND` |
| List | `recall {}` — every fact, for the older ones the block left out |
| When | Core instruction 10 (`agent-docs.ts`): save when the person corrects the agent or states a lasting preference; global for taste, document for this design's rules; never the current task's details |

## RPC and UI

RPC: `memory.list { docId? }`, `memory.remember`, `memory.forget` (zod: `memoryParams`); event `memory.changed`. `docId` picks the document scope; without one, the active document.

Settings → Memory (`MemoryPage.tsx`): two groups, Global and This document, each fact with its text, date and Forget; Add with a Global / This document switch; Open folder. The page reloads on `memory.changed`, so facts an agent saves appear while it is open.

## Not built yet

- A toast in the canvas when an agent saves a fact (today it shows as a tool call in the chat).
