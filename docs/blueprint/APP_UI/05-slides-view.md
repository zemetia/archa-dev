# App UI — 05: Slide View

← [APP_UI.md](../APP_UI.md) | [Blueprint INDEX](../INDEX.md) | [← 04 — Design panel](./04-design-panel.md)

**Built** on `zemetia/slides-view`. Code: `renderer/ui/SlidesView.tsx` (view), `renderer/lib/slides.ts` (pure logic, tested in `apps/desktop/test/slides.test.ts`), entry button in `renderer/ui/SlidesPanel.tsx`.

A Canva-like way to work on a deck: every slide stacked top to bottom at fit-width, scrolled vertically, with "+" between slides to add one at that spot. It covers the canvas inside the `<main>` card; the canvas stays mounted underneath, so going back keeps the camera.

---

## What a Slide Is

Same notion as the Slides tab ([APP_UI/01](./01-shell-tools-panels.md) → Left menu): a **visible top-level frame** of the page. There is no slide node type and no format change.

| Rule | Detail |
|---|---|
| Order | The page root's child order (`slideFrames(doc, rootId)`), the same order the Slides tab shows |
| Insert position | Slide position `at` maps to a child index: before slide `at`, or after the last slide (other top-level layers keep their index) |
| Canvas position | Right of the previous slide on its row (gap 80), stepping right past anything it would overlap (`placeSlide`); an empty page starts at 0,0 |
| New frame | `Slide N` (first free N), white fill, clip on, fixed size; one `insert` op → one undo step |
| Resize | One `update` of `width` / `height`; hug / fill axes become fixed so the size sticks. Children keep their positions (no scaling) |

---

## Size Presets

`SLIDE_PRESETS` in `lib/slides.ts`. A size that matches a preset is named by it, else `Custom W×H`.

| Group | Presets (px) |
|---|---|
| Presentation | 16:9 1920×1080 · 4:3 1600×1200 · 5:4 1500×1200 |
| Document | A4 portrait 794×1123 · A4 landscape 1123×794 · US Letter 816×1056 (96 dpi) |
| Social | Square 1080×1080 · Portrait post 4:5 1080×1350 · Story 9:16 1080×1920 |
| Custom | Width × height fields, 1–10000 px each (`parseSize`) |

A new slide defaults to the size of the slide before it (the first slide when added at the top; 1920×1080 on an empty page) — `defaultSizeAt`. The picker's first row is that size; one click adds it.

## Layout and Interaction

| Part | Behaviour |
|---|---|
| Open | Slides tab → **Slide view** button (it turns into **Back to canvas** while open). State: `slidesView` in the view store, not persisted |
| Header bar | **← Canvas** (back), title + slide count, **Add slide** (adds after the last slide) |
| Slide card | Page number, name, size menu, "Open on canvas". Picture fits the column width (max 1040 px) and is capped by window height for tall sizes; rendered by `useNodeThumb` (subtree-hash cache, [CACHE/01](../CACHE/01-layers-keys.md)) |
| Click | Selects the slide; the Design panel edits it. Empty space clears the selection |
| Double-click / Open on canvas | Leaves the view and frames that slide on the canvas (`revealNode`) |
| "+" between slides | Shows on hover of the gap; opens the size picker; the new slide is selected and scrolled into view |
| Size menu | Same picker, action Resize |
| Back | Header button, the Slides tab button or **Esc**; the canvas zooms to the selected slide |
| Slides tab while open | Clicking a thumbnail scrolls the view to that slide instead of moving the canvas |

Depth follows the owner's taste: slides float on the canvas colour with a two-layer shadow, popovers sit above them with a heavier one; no eyebrow labels.

Not built: dragging slides to reorder, editing layers inside the view (open on canvas instead), scaling content on resize.
